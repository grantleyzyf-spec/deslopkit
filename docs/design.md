# 设计说明：为什么这样造，以及和同类项目的差异

本文是 `deslopkit` 的设计理由与取舍记录。目标读者是贡献者与评审者：如果你要改规则、改闸门或改指标，
先读这一页，避免重新踩一遍已经踩过的坑。

## 1. 问题定义

中文与英文互联网上的「AI 文本去痕」项目，大致分成三代：

1. **提示词/规则清单**（`blader/humanizer`、`Anbeeld/WRITING.md`、各类「降 AIGC 率」Skill）：
   把「AI 写作特征」写成给模型看的指令，由模型执行改写。
2. **Agent 插件 + 门禁**（`ProfSynapse/DeSlop`、`humanizer-ru`）：在提示词基础上加入「先定位、再人工裁定、
   未过自查门禁不交付」的流程，部分项目附带扫描器。
3. **端到端产品**（`BypassAIGC`、`AI_paper`、各家商业降重站）：界面化，效果以截图与单例宣称。

三代共同的三个结构性缺陷：

* **不可复现**：改写由模型采样完成，同一输入两次输出不同 ⇒ 不能进 CI、不能回归、不能审计。
* **无保真校验**：没有人核对「改写有没有把数字、文号、书名、引号内术语改掉」。学术与公文场景里这是致命的。
* **不区分语域**：一套「活人感」规则套所有文体 ⇒ 把合规的机构腔、分点陈述、GB 连接号一起改坏；
   对课题报告、公文、期刊论文而言，这本身就是一种缺陷。

此外还有两个「工程外部性」问题：效果无法被第三方用同样代码复算；以及普遍不做诚实声明
（「保证降到 X% 以下」是无法验证的承诺）。

## 2. 我们的取舍

### 2.1 确定性优先，LLM 可选

核心引擎是**规则匹配 + 模板展开**：`rules/*.json` 里的正则负责定位，`rewriters.py` 负责展开替换。
好处是同一输入永远同一输出，可以写测试、可以进 CI、可以被审计。

需要更强改写能力的场景（例如整段重写）不是本项目要解决的问题；我们宁可「只做能确定性做对的那部分」，
并把剩余部分明确标为 `needs_review` / 仅提示，也不做「看起来改了但不可验证」的整篇重写。

### 2.2 保真护栏是一等公民

`fidelity.py` 在改写前抽取受保护片段：

| kind | 覆盖 |
|---|---|
| `url` / `email` | 链接与邮箱 |
| `doc_no` | 中文文号（如「渝教规办〔2026〕4 号」） |
| `std_no` | 标准号（如 `T 0646—2022`） |
| `book_title` | 《书名号》内的一切 |
| `zh_quote` | “中文引号”内的一切（术语、口号、引文） |
| `citation` | `[1]`、`[1,2]` 引用标记 |
| `percent` / `number` | 百分比与数字 |
| `latin_term` | 术语型拉丁串（`AI`、`GenAI`、`C-STEAM`、`5E`、`AI+`），**不含普通英文单词** |
| `keep` | 用户 `--keep` / `--keep-from` 指定的必保词（机构名、专名建议走这里） |

改写后按 `(kind, value)` 多重集比对：**丢失即违规，新增同样违规**（后者用于防模型编造数字）。
违规 ⇒ 该处改写回滚，并在 `rejected` 列表里给出原因。

两个实测教训写在这里，避免回退：

* **不要把机构名做成正则自动抽取**。`…小学 / …大学` 这类后缀会把前文任意汉字吞进匹配，
  实测「人工智能赋能中小学」被当成机构名，导致 `赋能→助力` 被误回滚。机构名交给用户 `--keep` 显式声明。
* **不要把普通英文单词当受保护片段**。否则英文文本里每个词都受保护，5/5 改写全部被回滚。
  术语用「token + 谓词」判定：含 `+`/`#`、含数字、全大写、或内部有大写字母（驼峰）。

### 2.3 语域决定规则开关

`register.py` 定义 5 套画像（`zh-gov` / `zh-academic` / `zh-forum` / `en-academic` / `en-essay`），
每套给出三件事：

1. **类别策略**：`fix`（自动改写）/ `review`（仅提示）/ `off`（不报）。
   例：`zh-gov` 下「分点陈述、提示性冒号、GB 连接号」属合规文体 ⇒ 只提示或完全不动；
   `zh-forum` 下它们才是需要清掉的痕迹。
2. **指标参照带**：句长 CV、段长 CV、短句占比的下限（见 `docs/metrics.md`）。
3. **闸门类别**：处理后必须清零的类别（`zh-gov` 只要求 `negation_pivot` 清零，`zh-forum` 还要求黑话与路标）。

判别顺序刻意写成「类别 → 策略」，而不是给每条规则写死「哪个语域改、哪个不改」，
这样新增语域只需加一套画像，不必改规则库。

### 2.4 交付闸门

`engine.rewrite()` 结束后跑 `_gate()`，六项检查全过才算通过（CLI `--exit-code` 可据此返回非 0）：

1. 保真护栏通过；
2. 该语域的闸门类别**可自动改写残留**清零（评审类命中不计入，但在报告里单列）；
3. 句长 CV 不下降（样本过小时列为「不适用」，或处理后仍高于参照带下限则放行）；
4. 段长 CV 同上；
5. 字数变动 ≤10%；
6. 无新增重复句。

第 3/4 条的小样本豁免来自实测：4 段短样例上 CV 受单句改写影响极大，硬判会把正常改写判红。

## 3. 与同类项目的直接对照

| 维度 | 提示词类 Skill | Agent 插件类（DeSlop 等） | 端到端降重产品 | **deslopkit** |
|---|---|---|---|---|
| 可否被代码调用 | ✗ | △（插件协议） | ✗ | ✓ 库 + CLI |
| 输出可复现 | ✗ | ✗ | ✗ | ✓ 确定性 |
| 可回归测试 | ✗ | 部分（扫描器） | ✗ | ✓ 44 用例 + CI |
| 保真校验 | ✗ | ✗ | ✗ | ✓ 受保护片段比对 + 回滚 |

| 指标可复算 | ✗（只给截图） | △ | ✗ | ✓ Markdown/JSON 双报告 |
| 人工参照带 | ✗ | ✗ | ✗ | ✓ 同语域实测口径 |
| 交付门禁 | 提示词约束 | ✓（思路被本项吸收） | ✗ | ✓ 代码化 6 项 |

| 中英双语 | 多为单一语言 | 多为单一语言 | 中文为主 | ✓ 双规则库 |

被明确吸收进本项目的社区成果：Wikipedia *Signs of AI writing* 的征候清单（英文规则库的定义来源）、

`humanizer-zh-academic` 的「噪声预算 / 语域适配」、中文降重项目的「学术语域优先」。

## 4. 明确不做的事

* 不做「保证通过某检测器」的承诺，也不针对具体检测器做对抗性优化（那会把工程问题变成军备竞赛，
  且结果不可验证）。
* 不做全篇 LLM 重写（不可复现、且最容易改坏事实）。
* 不自动抽取机构名等易误报的实体；这类词由用户显式声明。
* 不在文本里注入「人类噪声」（错别字、口语碎词、无意义插入语）——那是在制造缺陷，不是改善写作。

## 5. 后续方向

* 规则库扩展到繁体中文与日韩语（结构与 `zh.json` 相同）。
* 指标层增加「信息密度」与「段落推进度」探针，用于识别「同一观点换三种说法」的注水。
* 提供 GitHub Action（`deslopkit audit --exit-code` 作为写作仓库的 pre-commit 门禁）。
* 与本仓库配套的 `--baseline` 支持：读入外部检测报告命中区间，只对该区间做定点处理。
