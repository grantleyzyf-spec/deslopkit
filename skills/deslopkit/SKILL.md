# deslopkit · Agent Skill 入口

本 Skill 是一个**命令行工具的调用契约**：真正的实现在同仓库的 Python 包里
（`src/deslopkit/`）。作为 Agent，你的职责是：**判定语域 → 先审计 → 再改写 → 复核闸门与报告**，
并且**如实说明工具的边界**。

## 何时使用

- 用户拿一份成稿问「AI 味重不重 / 有多少机器痕迹」→ 走 `audit`（只诊断，不改动）。
- 用户要求「降痕迹 / 去 AI 味 / 按格式语域改一版」→ 走 `rewrite`，并**先确认语域**。
- 用户要求「改写但不要改坏数据、文号、书名、引文」→ 这正是本工具的保真护栏场景。

## 调用契约

```bash
# 0) 环境（任选其一）
pip install deslopkit        # 或 PYTHONPATH=<repo>/src python -m deslopkit

# 1) 诊断（只读）—— 必做，先看清痕迹分布
deslopkit audit <文件> --register auto --md audit.md --json audit.json

# 2) 改写（默认输出到目录，不改原文件）
deslopkit rewrite <文件> -o <输出目录> --register <语域> \
        --keep-from <原稿或素材文件> --md rewrite.md --json rewrite.json --exit-code

# 3) 复核
#    - rewrite.md 的「闸门检查」必须全部 ✅
#    - 「已应用改写」里 needs_review=是 的条目要人工过目
#    - 「使用边界」一节要原样转达给用户
```

语域取值：`zh-gov`（课题报告/公文/方案）、`zh-academic`（论文/研究报告）、
`zh-forum`（知乎/论坛/公众号）、`en-academic`、`en-essay`；不确定时先用 `auto`，
再看 `audit.md` 里的 `语域：` 字段，必要时显式指定。

## 硬纪律（写进本 Skill 的原因）

1. **先审计、后改写。** 没有 `audit` 基线就直接 `rewrite`，无法判断改动是否必要。
2. **必保词先声明。** 机构名、人名、地名、课程名、专有提法用 `--keep` 或 `--keep-from 原稿.txt` 传入；
   工具不会自动抽取机构名（自动抽取会误报并回滚正常改写）。
3. **闸门不过不算完成。** `--exit-code` 非 0 时，必须把「闸门检查」表里未过项原样告诉用户，并说明原因。
4. **不得声称检测器结果。** ⛔ 不许说「已降到 X%」「保证通过某检测」。
   统一口径：本工具降低的是**可数的机器写作痕迹**，不改变生成来源，也不承诺任何第三方检测器的数值。
5. **结构性改写要人工过目。** 翻案句重排在报告里标 `needs_review`，交付时提示用户复核。
6. **不要为了指标好看而改内容。** 指标是诊断工具，不是目标函数；`docs/metrics.md` 里写明了常见误读。

## 汇报格式（给用户）

```
语域 | 处理前后关键指标（句长CV / 段长CV / 命中类别计数）| 应用 N 处 / 回滚 M 处 / 仅提示 K 处
| 闸门：通过 or 未通过（未过项…）| 报告：<路径> 
| 边界提示：不改变生成来源、不承诺检测器结果；needs_review 条目需你确认
```

## 仓库内文档

- `docs/design.md`：设计理由与同类项目对照（含为什么不做 LLM 全篇重写）
- `docs/metrics.md`：指标定义、人工参照带、自建参照带的方法
- `docs/rules.md`：规则 JSON 格式、新增规则的步骤与纪律
- `docs/ethics.md`：**使用边界与伦理说明（交付前必读）**
